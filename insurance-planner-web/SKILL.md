# 保險規劃網站

## 任務目標

維護一個純前端保險規劃工作台：使用者可以從左側拖曳保險分類主項目或其子項目到右側規劃區，整理保障分類、保障項目與詳細細項。主分類拖曳會建立完整分類並帶入該分類全部預設子項目；子項目拖曳只加入被拖曳的單一子項目。網站目前使用單一 HTML/CSS/JavaScript 檔案，狀態保存於瀏覽器 `localStorage`。

## 適用時機

使用者要求以下任一項目時使用本 Skill：

- 修改保險規劃網站或 `insurance-planner-web`。
- 修改保險分類、子選單、保障項目、細項、拖曳、排序或展開收合。
- 修改保障項目編輯 Dialog 或查看完整細節表單。
- 修改 DesignMD 視覺樣式、版面、標頭、卡片或工作區。
- 修改網站快取、Cache Busting 或 HTTP response headers。
- 部署、重建、檢查或驗證此網站 Docker。

## 目前功能規則

### 左側選單

- 「保險分類」是階層式主選單。
- 主分類可以點擊展開或收合，也可以直接拖曳到右側。
- 主分類拖曳到右側時建立完整分類，並加入該分類全部預設子項目。
- 主分類旁不應有「加入」按鈕；加入分類一律透過拖曳。
- 左側同時間只能展開一個主分類。
- 主分類底下的子項目才是拖曳來源。
- 子選單展開狀態保存於 `localStorage`。
- 子項目已加入右側對應分類時，顯示已加入狀態並禁止重複拖曳。

### 拖曳與分類限制

- 子項目拖到右側空白規劃區時：
  - 自動建立該子項目所屬的主分類。
  - 只加入被拖曳的子項目，不要自動加入該分類的所有預設項目。
- 子項目拖到已存在的正確主分類時直接加入。
- 不同主分類的子項目不可亂放，例如壽險子項目不能放進醫療險。
- 錯誤放置時拒絕操作並顯示原因。
- 同一主分類內同名項目不得重複。
- 主分類是有效的拖曳來源；拖曳主分類應建立完整分類。
- 子項目是有效的拖曳來源；拖曳子項目只建立或更新其所屬分類，不得加入其他分類。
- 右側保障項目可在同一分類內上下拖曳排序。
- 右側保障項目拖到同欄位的其他分類時，仍依分類歸屬拒絕錯誤放置；拖到不同欄位時，視為複製到另一個獨立方案，來源項目保留。
- 右側保障項目不可跨到其他主分類；其 `categoryId` 必須與目標分類一致。
- 跨欄位複製時，只有目標欄位同一分類內已有同名項目才拒絕；其他欄位的同名項目不影響此次操作。
- 左側主分類或子項目拖到右側既有卡片時，必須從目標卡片的 `laneId` 傳遞實際欄位，不得使用預設的 `lane-1`。
- 保障項目拖出所有分類框後放開時，移除該項目並保存狀態；若使用按鈕刪除，必須先確認。
- 右側分類不可拖回左側刪除；刪除分類只能使用右側分類的 `×` 按鈕。
- 右側分類的 `×` 刪除按鈕必須先確認。
- 拖曳到同一分類卡片內的其他位置時，不得誤刪。
- 右側分類卡片本身目前可拖曳排序時，不能與子項目拖曳事件混淆。

### 展開與收合

- 左側主分類：同時間最多一個展開；點擊目前展開的分類可全部收合。
- 右側保障分類：每張卡片獨立展開或收合，彼此不應互相關閉。
- 右側分類的整個標題列可點擊展開／收合。
- 右側標題列不顯示展開／收合按鈕；刪除按鈕 `×` 仍保留，且點擊刪除不得觸發收合。

### 編輯與查看

保障項目支援：

- 編輯名稱。
- 編輯保障內容說明。
- 從 Dialog 右側預設細項清單拖曳詳細細項。
- 詳細細項包含名稱與內容。
- 詳細細項可上下排序、編輯與刪除。
- 詳細細項同名不得重複。
- 不顯示「新增細項」或「新增自訂細項」按鈕；所有保障項目與詳細細項只能透過既有拖曳來源加入。
- 支援獨立的「查看完整細節」唯讀 Dialog，顯示名稱、保障說明及所有詳細細項。

## 資料保存

- 主要狀態 key：`insurance-planner-state-v1`。
- 左側區塊狀態 key：`insurance-planner-sections-v1`。
- 左側主分類子選單狀態 key：`insurance-planner-category-menu-v1`。
- 狀態保存於使用者瀏覽器 `localStorage`，不同瀏覽器或裝置不共享。
- 新增、編輯、刪除、排序、移動、展開／收合都要呼叫保存函式。
- 載入舊資料時要補上 `categoryId`、`content` 與 `details`，並去除重複項目。
- 不可因部署、重建 Docker 或強制重新整理而清除 `localStorage`。

## 視覺與版面

目前視覺參考 DesignMD 的淺色、編輯式卡片工作區方向：

- 淺灰紫色背景。
- 白色頂部導覽列與白色內容卡片。
- 小型固定標頭，不使用大型 Hero。
- 內容區優先，卡片有柔和圓角與輕微陰影。
- 藍色作為主要互動色。
- 不同保險分類使用固定不同顏色，至少套用在分類卡片外框／左側色帶、分類圖示與保障項目邊框；同一分類在不同規劃欄仍使用相同顏色。
- 左側主分類與子項目也必須套用所屬分類顏色，包含主分類色帶、圖示、文字／箭頭重點色及子項目邊框；已加入狀態提示可維持綠色。
- 左側是清楚的階層式選單，右側是主要規劃工作區。
- 工作區保持單頁視窗高度。
- 藍圖區右上角提供欄數循環按鈕，依序切換 `1 欄 → 2 欄 → 3 欄 → 1 欄`。
- `1 欄`時保障分類垂直排列；`2 欄`或`3 欄`時在藍圖區分欄排列，保留卡片順序與各自資料，方便比較不同規劃。
- 每個規劃欄本身就是唯一的可見拖曳區；不要在欄位外另外保留全頁大型空白拖曳區。
- 空白欄位在自己的框格內顯示拖曳提示，但不得用固定的大型最小高度撐開欄位。
- 收合的分類卡片只保留標題列高度；`.lane` 與 `.lane-cards` 不得以固定 `min-height` 讓藍框變大，多欄時各欄依自己的內容高度排列。
- 欄數偏好保存於 `localStorage`；手機版為可讀性自動回到單欄顯示，不改變保存的桌面欄數偏好。
- 使用者指定目前頁面所有元素的 `padding` 統一為 `3px`，以頁面最後的全域 CSS 規則覆蓋元件原有內距；修改時不得自行恢復較大的內距。
- 桌面版內容超出時在內部滾動，但隱藏捲軸外觀。
- 手機版可恢復一般頁面滾動，避免內容被固定區域遮住。
- 修改視覺時不要破壞既有拖曳、點擊及表單功能。

## 禁止快取

Nginx `nginx.conf` 目前應對首頁與一般路徑回傳：

```http
Cache-Control: no-store, no-cache, must-revalidate, proxy-revalidate, max-age=0
Pragma: no-cache
Expires: 0
```

版本號網址可使用：

```text
http://10.145.119.12:18084/?v=20260903
```

每次正式部署若需要明確 Cache Busting，更新網址的 `v` 版本值；不要把版本參數誤當成唯一的禁止快取措施。

## 執行流程

1. 先唯讀檢查遠端容器、Port 與目標檔案。
2. 從遠端抓回最新版 `site/index.html` 到專用暫存目錄。
3. 讀取完整目標區塊後再修改，不要猜測目前版本。
4. 若要套用 DesignMD，先透過 DesignMD 取得設計系統與 token，再只選一套設計系統使用；不要混用多套品牌 token。
5. 使用 UTF-8 修改 HTML/CSS/JavaScript。
6. 從 HTML 抽出 `<script>` 到暫存目錄，執行：

```bash
node --check <temporary-script.js>
```

7. 上傳正式 `index.html`、必要的 `Dockerfile` 與 `nginx.conf`。
8. 在遠端執行：

```bash
cd /home/hch/docker-webs/insurance-planner
docker-compose -p insurance-planner up -d --build
docker exec insurance-planner-web nginx -t
```

9. 驗證容器：

```bash
docker ps --filter name='^insurance-planner-web$'
```

10. 驗證網站及禁止快取 Header：

```bash
curl -fsS -D - -o /dev/null 'http://10.145.119.12:18084/?v=<version>'
```

11. 驗證 `18083` 仍回應正常。
12. 清理專用暫存目錄；不要把測試腳本、抽出的 JS、HTTP 回應或截圖留在專案目錄。

## 規則與限制

- 不執行 `docker prune`、刪除 Volume、刪除既有容器或 reset 使用者資料，除非使用者明確要求並確認。
- 網站內的分類或項目刪除也必須保留確認詢問；取消確認時不得呼叫 `saveState()` 或改變狀態。
- 不修改 `18083` 既有網站。
- 不修改 ComfyUI、GPU 配置、模型或遠端影片生成服務，除非使用者另外明確授權。
- 不新增後端、資料庫或依賴套件，除非需求明確需要。
- 不把 `localStorage` 資料當成跨裝置資料庫。
- 不將保險規劃 UI 描述成正式保險建議、報價或具法律效力的金融意見。
- 修改前必須先備份或至少抓回現行遠端檔案到專用暫存目錄；若要正式部署前建立遠端備份，備份檔不得覆蓋原檔。

## 常見陷阱

- 不要把 `localStorage` 當成跨裝置資料庫，也不可因部署或強制重新整理而清除狀態。
- 不要修改 `18083`，也不要動 ComfyUI。
- 不要把網址 `v` 參數當成唯一的禁止快取措施；Nginx 仍須回傳 no-cache Header。
- 左側拖到規劃二或規劃三時，必須傳遞實際 `laneId`，不可預設成 `lane-1`。
- 不要用固定 `min-height` 撐開收合卡片或規劃欄。
- 套用 DesignMD 時只選一套設計系統，不要混用多套品牌 token。
